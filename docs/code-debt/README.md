## Size legend

- **XS** — trivial/mechanical: delete a dead line, rename, add a prop, add an enum.
- **S** — focused: one bug fix, or one helper adopted at 1–2 call sites.
- **M** — bounded refactor: helper consolidation across modules, one module split,
  or one per-resource route extraction. Largest size we file; nothing above M.

## Filing convention

Each epic file lists its issues as a `### E.N — Title` section with:

- **Size** — XS/S/M.
- **Triage** — `ready`, `blocked-by #E.N` (native blocked-by at filing),
  `needs-input`, or `needs-definition`.
- **Problem / Result / Scope / Verify / Tests / Deps** — the fields ghflow's
  `triage:ready` requires (scope + verification criteria concrete enough to implement).

`Verify` names the gate command; `Tests` names the test to add (or the existing
test that already protects). `Deps` uses `E.N` ids until real issue numbers exist;
at filing, replace `blocked-by #E.N` with the resolved issue number.

### Machine-readable manifest

`filing-manifest.json` is the machine-readable projection of these files
(generated by `scripts/gen_filing_manifest.py`; single source = the markdown).
It carries `impl_model`, `parent`, and dependency fields. `FILING.md` gives the
filing worker a deterministic procedure. File in list order — it is already
dependency-safe. Multi-module M items are subdivided into `X.Ya`/`X.Yb`… slices
(one module per slice) so a local model only ever holds one module in context.

## Implementation model

Each issue carries a provisional `impl_model` tag: **74 `local`**, **57 `strong`**.

- **`local`** — mechanical, single-module-ish, gate-checked. Suitable for a small
  quantized model (e.g. `qwen3.8-27b-4bit`, Flint) iterating red/green against the
  test suite. The multi-module M items were subdivided into per-module slices so a
  local model only ever holds one module in context.
- **`strong`** — subtle invariants, large/high-context (god-module splits,
  multi-provider), or security-adjacent. Use a frontier or larger non-quantized
  model.
